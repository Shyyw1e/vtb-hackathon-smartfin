# SmartFin: мультибанковский финансовый помощник

**SmartFin** — это проект, созданный в рамках хакатона, который демонстрирует, как можно построить современный мультибанковский финансовый помощник на базе инициативы Банка России «Открытые финансы». Система агрегирует данные о счетах и транзакциях из нескольких банков, позволяет управлять согласием клиента и токенами доступа, а также дополняет сырые транзакции аналитикой на основе машинного обучения. Мобильное приложение на Flutter использует единый API и показывает пользователю личный финансовый дашборд.

## Возможности

* **Агрегация нескольких банков** – backend предоставляет эндпоинты `/api/v1/accounts` и `/api/v1/transactions`, которые получают данные из всех подключенных банков. Внутри для каждого банка (VBank, ABank и SBank) создаются отдельные клиенты, которые получают access‑токены через токен‑эндпоинты банков и вызывают API. Обработчик данных объединяет и сортирует результаты; поддерживаются параметры `since` и `limit`.

* **Управление согласием и токенами** – перед обращением к API банка система проверяет, дал ли пользователь действительное согласие. Менеджер согласий кеширует активные согласия, опрашивает ожидание и отзывает их по запросу. Менеджер токенов получает токены каждого банка через `/auth/bank-token`, сохраняет их в Redis с временем жизни, равным сроку действия токена.

* **Безопасная аутентификация** – обработчик `auth` реализует регистрацию и вход, хеширование паролей, выпуск JWT, обновление и ротацию токенов. Пароли никогда не хранятся в открытом виде, все запросы выполняются через TLS 1.2+. В конфигурации можно включать/выключать функции, такие как paywall, поддержка ГОСТ‑TLS и VRP‑платежи.

* **Инсайты и машинное обучение** – эндпоинт `/api/v1/insights/overview` обращается к внешнему сервису на Python, который анализирует транзакции. ML‑сервис из каталога `ml/` загружает TF‑IDF‑векторизатор и классификатор на базе логистической регрессии для категоризации транзакций, подсчёта топ‑мерчантов, суммарных потоков средств и обнаружения подписок. Сервис предоставляет эндпоинт FastAPI `/score`, который принимает список транзакций и возвращает категории и агрегированную аналитику.

* **Flutter‑приложение** – каталог `frontend/` содержит кроссплатформенное приложение на Flutter. Пользователь может подключить несколько банков через OAuth2, увидеть общий баланс, списки транзакций и графики, просмотреть инсайты от ML‑сервиса и увидеть пример платной функции. Приложение общается только с backend; токены на устройстве не хранятся.

* **Контейнеризированное развертывание** – файл `docker-compose.yml` описывает сервисы: Postgres, миграции, Redis, Go‑API (`api`), ML‑сервис (`ml`), Swagger‑UI и статический хостинг для Flutter-сборки. Благодаря Docker и Docker Compose можно запустить всю систему локально за несколько команд.

## Архитектура

Проект построен по микросервисной архитектуре:

| Компонент                                                   | Описание                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Go‑API (`cmd/api`)**                                      | Основной HTTP‑сервер на Chi. Предоставляет REST‑эндпоинты (`/api/v1/`), загружает конфигурацию из переменных среды, инициализирует клиентов банков с безопасным TLS и таймаутами, подключает middleware (логирование, лимитирование, CORS) и обслуживает Swagger. |
| **Клиенты банков (`internal/banks`)**                       | Инкапсулируют обращение к OpenAPI банков. Каждый клиент умеет получать счета и транзакции, обрабатывать ошибки согласия (ожидание/истечение), повторять временные ошибки и добавлять идемпотентные ключи.                                                         |
| **Менеджер согласий (`internal/consent`)**                  | Управляет жизненным циклом согласий: создаёт новые, опрашивает их статус, кеширует активные ID и отзывает ненужные. Состояние согласий хранится в Postgres и Redis.                                                                                               |
| **Менеджер токенов (`internal/auth`)**                      | Получает access‑токены банков по client credentials и кеширует их. Использует singleflight, чтобы объединять параллельные запросы, и обновляет кеш до истечения срока действия.                                                                                   |
| **Службы агрегации (`internal/services/banks_service.go`)** | С помощью errgroup получают данные сразу из всех подключенных банков, объединяют результаты и сортируют по времени. Эти функции вызывают REST‑обработчики, скрывая сложность параллельных вызовов.                                                                |
| **Аутентификация (`internal/handlers/auth.go`)**            | Реализует регистрацию, вход, хеширование паролей, выдачу токенов, хранение refresh‑токенов и сброс пароля; включает rate‑limiting для защиты от брутфорса.                                                                                                        |
| **ML‑сервис (`ml/app.py`)**                                 | Небольшой FastAPI‑сервис на Python, загружает TF‑IDF‑векторизатор и модель логистической регрессии, классифицирует транзакции, вычисляет агрегации и возвращает инсайты (например, долю подписок).                                                                |
| **База и кеш**                                              | Postgres хранит пользователей, refresh‑токены, токены банков, согласия, счета, транзакции и кэшированные инсайты. Redis кеширует краткоживущие данные (access‑токены, инсайты).                                                                                   |
| **NATS (опционально)**                                      | В конфигурации предусмотрена шина сообщений NATS; она может использоваться для публикации событий (новые транзакции, действия пользователя).                                                                                                                      |

## Запуск локально через Docker

1. **Клонировать репозиторий**:

   ```bash
   git clone https://github.com/Shyyw1e/vtb-hackathon-smartfin.git
   cd vtb-hackathon-smartfin
   ```

2. **Скопировать пример окружения и заполнить секреты** (client ID и client secret для каждого банка, ключ шифрования и т. д.). Эти данные можно получить в регистре Open Banking.

   ```bash
   cp .env.example .env
   # отредактируйте .env, установив VBANK_CLIENT_ID, VBANK_CLIENT_SECRET, ABANK_CLIENT_ID и т.д.
   ```

3. **Собрать и запустить сервисы**:

   ```bash
   docker compose build
   docker compose up
   ```

   При первом запуске контейнер миграций создаст таблицы. API будет доступен на `http://localhost:8080`, ML‑сервис — на `http://localhost:5010`, Swagger UI — на `http://localhost:8081`.

4. **Открыть Swagger UI** в браузере, чтобы изучить API и сделать пробные запросы. UI обслуживается сервисом `swagger` и подгружает `openapi.yaml` из репозитория.

5. **Запустить мобильное приложение Flutter**. Установите Flutter >= 3.0, выполните `flutter pub get` в каталоге `frontend/`, затем `flutter run` или `flutter build apk`. В `docker-compose.yml` сервис `apk` может раздавать собранный APK через Nginx.

## Конфигурация

Конфигурация загружается через пакет `internal/config`. Значения берутся из переменных среды и YAML‑файла, указанного в `CONFIG` (по умолчанию `config.yaml`).

* **app** – имя, окружение (`dev`, `stage`, `prod`) и адрес HTTP. Флаги `paywall`, `gost_enabled`, `vrp_enabled` включают дополнительные возможности.
* **postgres** и **redis** – параметры подключения к Postgres и Redis.
* **banks** – список банков с URL API, URL авторизации и scopes; позволяет добавлять банки без изменения кода.
* **security** – публичные ключи для проверки JWT, общий секрет для вызова ML‑сервиса, ключ шифрования.
* **ml** – хост и порт Python‑сервиса.
* **limits** – максимальное количество счетов и транзакций в одном ответе.

## Схема базы данных

SQL‑миграции в каталоге `migrations/` создают схему базы. Начальная миграция создаёт таблицы пользователей, refresh‑токенов, согласий, токенов банков, счетов, транзакций и состояния синхронизации. Последующие добавляют поля для истечения срока согласия и ожидания. Применить миграции вручную можно так:

```bash
docker compose run migrate up
```

## Основные эндпоинты API

| Метод и путь                                 | Описание                                                                                                        |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `POST /auth/signup`                          | Создать пользователя, хеширует пароль и возвращает JWT и refresh‑токен.                                         |
| `POST /auth/login`                           | Аутентифицировать пользователя и выдать JWT/refresh‑токен.                                                      |
| `GET /api/v1/banks`                          | Показать подключённые банки (согласия) для текущего пользователя.                                               |
| `POST /api/v1/banks/{bank}/consents/request` | Убедиться, что у пользователя есть согласие с банком; вернуть URL для авторизации.                              |
| `DELETE /api/v1/banks/{bank}/consents/{cid}` | Отозвать согласие по ID.                                                                                        |
| `GET /api/v1/accounts`                       | Вернуть объединённый список счетов из всех подключенных банков. Требует аутентификации.                         |
| `GET /api/v1/transactions`                   | Вернуть транзакции из выбранного банка. Поддерживает параметры `since` (по умолчанию 30 дней), `limit`, `sort`. |
| `GET /api/v1/insights/overview`              | Вызвать ML‑сервис и получить категории, топ‑мерчантов, cashflow и инсайты.                                      |
| `GET /api/v1/insights/categories`            | (Заготовка) Вернуть статистику по категориям.                                                                   |

Полная спецификация API находится в `openapi.yaml` и доступна через Swagger UI.

## API сервиса машинного обучения

ML‑сервис на Python предоставляет единственный эндпоинт `/score`. Он принимает JSON с идентификатором пользователя и списком транзакций, применяет TF‑IDF и логистическую регрессию и возвращает:

* **categories** – сопоставление ID транзакций и предсказанных категорий;
* **categories_ordered** – категории, отсортированные по общей сумме;
* **merchants** – топ‑мерчанты и сумма расходов;
* **cashflow** – суммарные входящие и исходящие средства;
* **insights** – ключевые выводы (например, доля подписок, если категория «subscriptions» занимает более 30 % трат).

Для безопасного вызова в заголовок `X-Signature` нужно добавить HMAC‑подпись, вычисленную по секрету. Пример:

```bash
curl -X POST http://localhost:5010/score \\
  -H 'Content-Type: application/json' \\
  -H 'X-Signature: <hmac>' \\
  -d '{\"user_id\":1,\"transactions\":[{\"id\":\"1\",\"mcc\":5411,\"amount\":1000,\"balance\":0,\"description\":\"Пятёрочка\",\"date\":\"2025-10-01T10:00:00Z\"}]}'`
```

Сервис вернёт JSON‑ответ с категориями и агрегатами; подробности — в `ml/README.md`.
